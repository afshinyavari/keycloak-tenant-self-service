# R2.4 with strict field validation

Run after the setup in `docs/production-coverage.md` (needs `$E` and the guard-test
namespaces). `--validate=strict` makes the server reject a field that is not in the schema
instead of pruning it silently.

```bash
cat <<EOF | oc $E apply --dry-run=server --validate=strict -n guard-test-a -f -
apiVersion: keycloak.hostzero.com/v1beta1
kind: KeycloakRole
metadata:
  name: coverage-check
spec:
  clientRef:
    name: someone-elses-client
    namespace: guard-test-b
  name: hijack
  definition: {}
EOF
```

- `unknown field "spec.clientRef.namespace"`: references cannot name another namespace. R2.4 passes.
- `created (server dry run)` even with strict validation: the schema accepts the field; check it with
  `oc get crd keycloakroles.keycloak.hostzero.com -o jsonpath='{.spec.versions[0].schema.openAPIV3Schema.properties.spec.properties.clientRef}'`.
